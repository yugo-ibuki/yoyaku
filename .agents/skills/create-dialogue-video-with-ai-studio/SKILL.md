# AI Studio で会話動画を制作する

Google AI Studio では確定した会話音声だけを作る。完成 MP4 は、保存した音声と利用可能な画像・映像素材を使って別工程で組み立てる。

## 制作入力を確定する

まずプロジェクト内の台本、制作メモ、既存素材、レンダラー、ローカル指示を調べる。依頼または保存済み資料で台本、登場人物、声の方向性、素材が十分に決まっていれば、そのまま自律的に進める。人物の同一性や使用素材など、結果を大きく変える必須情報だけが欠ける場合に質問する。

話者ごとに次を一つの対応表へ固定し、音声生成から動画検証まで同じ ID を使う。

- 制作用の安定したキャラクター ID
- 視聴者に見せる名前または役割名
- AI Studio 内の話者識別子
- 選択した声と声の演技指示
- 発音上の注意

字幕や画面上の話者名には、ユーザーが指定した名前または役割名を使う。声名、年齢表現、声質などの制作情報を表示名にしない。

動物が画面上の話者なら、**必須サブスキルとして `create-animal-dialogue-video` を使い**、個体の同一性、構図、口・くちばし、聞き手の動き、素材の扱いを決める。特定の動物、人数、左右配置、作品例の値を既定値にしない。

## AI Studio で音声を生成する

1. API ではなく、利用可能なブラウザ/CUA 操作ツールで Google AI Studio の Speech UI を開く。依頼者が AI Studio を指定しているため、通常は UI を使う。
2. 実行時の画面を読み、ログイン中のアカウント、選択中のプロジェクト、音声モデル、生成モード、対応話者数、入力長などの制限、声、スタイル、言語を確認する。URL のユーザー番号、過去のプロジェクト名、モデル名、ボタン名、二人という人数を固定しない。意図したアカウントやプロジェクトであると判断できない場合は、生成を実行する前に止める。
3. 確定した台本を発話順どおりに入力し、対応表に従って各ブロックへ話者と声を割り当てる。台詞本文と演技指示を混同しない。発音調整の入力表記が確定台本と異なる場合は両方を保存し、台詞の意味を勝手に変えない。UI が変わっていたら、表示中の操作要素と必要に応じて Google の公式 Speech/TTS 資料を基準に適応する。
4. 実行前に、意図した台本、AI Studio への正確な入力、話者対応、モデル、声、スタイル、プロジェクト、確認日時をローカルの実行記録へ保存する。記録形式には [references/run-record.md](references/run-record.md) を使える。
5. 音声を生成し、UI 上で再生して全編を確認する。実際の発話、話者、声の一貫性、発音、欠落、重複、順序、文頭・文末の切れ、不要音を、意図した台本と照合する。生成成功の表示だけで合格にしない。
6. 合格した音声を、その画面から移動、再読み込み、別の生成を行う前にダウンロードする。AI Studio の画面状態や履歴へ保存を委ねない。ダウンロードした WAV などの原本を変換せずプロジェクト内へ保存し、形式・再生時間・音声ストリームを確認して SHA-256 を記録する。制作形式への変換が必要なら原本とは別ファイルにする。
7. 発話、話者、発音、品質に問題があれば台本または設定を修正し、再生成後の音声を改めて全編確認する。採用音声が変わった時点で、以前の字幕時刻、話者ターン、口の動き、派生動画はすべて無効とする。

AI Studio の TTS は音声出力であり、動画生成完了とは扱わない。API キーや認証情報を記録へ入れない。課金設定、サブスクリプション、プロジェクト権限を変更しない。

### 一回の生成に収まらない場合

現在の UI またはモデルの話者数・入力長の制限に台本や出演者が収まらない場合だけ、完結した発話または自然な場面境界で管理可能なクリップへ分ける。通常の台本が一回で安定して生成できるなら分割しない。

- 全クリップで同じキャラクター ID と声の対応を維持する。各回の UI で割り当てを再確認し、画面上の一時的な Speaker 番号を人物 ID の代わりにしない。
- 原則として一つの発話の途中で切らない。制限上避けられない場合は、意味と抑揚を損なわない境界を選び、結合箇所を要確認として記録する。
- 各クリップを個別に全編確認し、採用した原音を次の生成や画面移動の前にダウンロードしてハッシュ化する。
- 最終順序、各クリップの入出点、ゲインや形式変換、境界ごとの意図した間、フェードの有無を連結レシピへ保存する。間を一律の秒数にせず、台本と実際の会話を聞いて決める。
- 原音を残したままレシピどおりに一つの最終音声へ組み立てる。全台本の欠落・重複・順序、継ぎ目のノイズや不自然な間、キャラクターごとの声質・音量・話速の連続性を通しで監査する。
- 連結した最終音声の SHA-256 を記録し、それだけを実測タイムラインの音声正本とする。クリップまたは連結レシピを変えたら最終音声を再作成し、旧タイムラインと派生動画を無効にする。

## 音声から MP4 を制作する

1. 採用音声のハッシュと、照合済みの正確な台本を制作入力として固定する。
2. **必須サブスキルとして `sync-dialogue-video` を使う。** 実際に聞こえる音声から話者ターンを確認し、その中で確定台本を強制アラインメントする。字幕、話者交代、口の動きは同じ実測タイムラインから作る。
3. 利用可能な画像・映像素材と制作仕様を確認し、現在の登場人物、画面比率、解像度、フレームレートに合わせてレンダラーを作成または調整する。既存作品のレンダラーは参考にできるが、その人物、配置、尺、タイミングを引き継がない。
4. 発話中は確認済み話者だけの口またはくちばしを動かす。聞き手には閉じた口、まばたき、呼吸、視線など、人物に合う控えめな反応を使う。
5. 完成 MP4 の映像・音声ストリーム、尺、先頭と末尾、全話者交代、字幕の全文と境界、発話者だけの口の動き、聞き手、キャラクターの同一性を確認する。実際のフレームも抜き出して目視する。

4.2 秒などの固定値、均等割り、文字数、字幕カードの長さから話者ターンを作らない。無音区間だけでも話者交代を決めない。

## 保存物と完了条件

プロジェクトの既存構成に合わせ、少なくとも次を一緒に保存する。

- ダウンロードした採用音声原本の実体と SHA-256。分割時は全クリップ、連結レシピ、連結した最終音声も含む
- 意図した最終台本と、AI Studio に入力した正確な文字列
- キャラクター ID、表示名、AI Studio 話者、声の対応表
- アカウントの識別に必要な非機密情報、プロジェクト、モデル、声、スタイル、言語、生成日時
- 入力素材、生成物、変換工程を追える来歴
- 採用音声から作り直した実測タイムラインと同期検証結果
- 完成 MP4 とその検証結果

「画面で生成済み」「音声を保存済み」「音声内容を確認済み」「MP4 を制作済み」「同期を目視確認済み」を別々に報告する。公開、アップロード、push、課金変更は、明示された依頼に含まれない限り行わない。
